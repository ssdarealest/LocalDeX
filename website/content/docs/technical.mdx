An in-depth technical analysis of how **LocalDeX** runs Samsung DeX natively on a Galaxy device's own screen with no external display, no dock, no PC, no cables, and no root access.

## 1. System Architecture

```text
LocalDeX App ──(Loopback ADB over TLS 1.3, 127.0.0.1)──▶ adbd Daemon
     │  1. Push bundled scrcpy-server v3.1 to /data/local/tmp/scrcpy-server.jar (SHA-256 verified)
     │  2. app_process / com.genymobile.scrcpy.Server new_display=<WxH/DPI>
     │  3. wm set-display-windowing-mode -d <displayId> 5   (force WINDOWING_MODE_FREEFORM)
     │  4. Open loopback video and control sockets (tunnel_forward=false, port=27183)
     ▼
scrcpy-server ──▶ Creates trusted virtual display ──▶ Samsung One UI triggers DeX desktop
     │  H.264/H.265 stream ──▶ MediaCodec (KEY_LOW_LATENCY = 1) ──▶ Fullscreen SurfaceView
     ◀─ Multi-mode input packets (Trackpad, Touch, S-Pen, Pointer Capture Mouse, Gamepad)
```

The application runs **100% in pure Kotlin** and never shells out to an external `adb` CLI binary. It establishes direct TCP/TLS connections to Android's internal `adbd` on `127.0.0.1`.

## 2. The ADB Loopback Layer (`:core:adb`)

### Wire Protocol Framing

ADB communication follows the standard 24-byte binary packet framing (`AdbMessage.kt`):

- **Command:** 4-byte integer (`CNXN`, `AUTH`, `OPEN`, `OKAY`, `CLSE`, `WRTE`).
- **Arg0 & Arg1:** Stream IDs and protocol versions.
- **Data Length:** Length of payload in bytes.
- **Data Checksum:** Byte sum payload checksum (`sum(b & 0xFF)`).
- **Magic:** Bitwise inverted command integer (`command ^ 0xFFFFFFFF`) used for header validation.

### Pure-Kotlin Cryptography (`AdbCrypto.kt`)

Android Wireless Debugging enforces mutual TLS authentication:

1. **RSA-2048 Keypair:** Generated via BouncyCastle (`bcprov-jdk18on`).
2. **Self-Signed X.509 Certificate:** Standard self-signed certificate built via BouncyCastle's `JcaX509v3CertificateBuilder`.
3. **Key Persistence:** Private key and certificate stored privately inside app internal storage (`context.filesDir`).

### mDNS Discovery & TLS 1.3 Pairing

- **Discovery:** Android's `NsdManager` (`AdbDiscoveryManager.kt`) scans for `_adb-tls-pairing._tcp.` and `_adb-tls-connect._tcp.`.
- **Inline Notification Reply:** Uses a foreground notification with `RemoteInput` (`PairingReplyReceiver.kt`) so the user submits the 6-digit PIN while staying on Developer Options.
- **TLS 1.3 Pairing Client (`AdbPairingClient.kt`):** Authenticates the local RSA-2048 certificate with `adbd` over TLS 1.3.

### Self-Healing Permission Grant

Immediately upon successful pairing, LocalDeX executes:

```sh
pm grant org.localdex android.permission.WRITE_SECURE_SETTINGS
```

Because `WRITE_SECURE_SETTINGS` has protection level `signature|privileged|development`, shell UID `2000` can grant it to installed packages. Once held, `AdbPermissionManager.ensureWirelessDebuggingEnabled()` writes `Settings.Global.putInt(..., "adb_wifi_enabled", 1)` on launch.

## 3. Virtual Display Creation & One UI Desktop Mode

### Trusted Virtual Display (`scrcpy-server`)

```sh
CLASSPATH=/data/local/tmp/scrcpy-server.jar app_process / com.genymobile.scrcpy.Server \
    3.1 scid=0 log_level=info tunnel_forward=false port=27183 \
    new_display=1920x1080/240 video_codec=h264 video_bit_rate=16000000 max_fps=60 \
    audio=false control=true stay_awake=true power_off_on_close=false cleanup=true
```

Running inside `app_process` under shell UID (`2000`) grants permission to call `DisplayManager.createVirtualDisplay()` with private/trusted flags, triggering Samsung One UI to launch DeX on Display ID `N`.

### Forcing Freeform Windowing on Android 16+ (One UI 8.5/9)

On newer Android releases, virtual displays can default to fullscreen windowing unless overridden via AOSP's `DisplayWindowSettings`:

```sh
wm set-display-windowing-mode -d <displayId> 5   # 5 = WINDOWING_MODE_FREEFORM
```

LocalDeX also toggles global desktop settings via `AdbPermissionManager`:

- `settings put global enable_freeform_support 1`
- `settings put global force_resizable_activities 1`
- `settings put global force_desktop_mode_on_external_displays 1`

### Why Virtual Displays Beat Overlay Displays

Android's simulated secondary displays (`overlay_display_devices`) suffer from two critical blockers:

1. **Un-hideable Preview Window:** `OverlayDisplayWindow` renders an un-hideable 0.5x preview box clamped over the primary display.
2. **SystemUI Caption Crash:** On One UI 8/9, dragging a window caption on an overlay display crashes `wmshell.main` with a `NullPointerException` (`DesktopModeVisualIndicator` constructed with a null display context). Virtual displays created via `scrcpy-server` bypass this path entirely.

## 4. Hardware-Accelerated Video Pipeline (`:core:scrcpy`)

`VideoStreamDecoder.kt` connects directly to `127.0.0.1:27183` over TCP (`tcpNoDelay = true`), reads the 64-byte device header, codec ID (`h264` / `h265`), and initial dimensions, and configures `MediaCodec` with `KEY_LOW_LATENCY = 1` and `KEY_OPERATING_RATE = Short.MAX_VALUE` directly onto the `SurfaceView`'s `Surface` for zero-copy rendering.

## 5. ADB Equivalents Quick Reference

| LocalDeX Operation | ADB Shell Equivalent |
| :--- | :--- |
| **Pairing** | `adb pair 127.0.0.1:<pairing_port> <pin>` |
| **Connecting** | `adb connect 127.0.0.1:<connect_port>` |
| **Push Server** | `adb push scrcpy-server /data/local/tmp/scrcpy-server.jar` |
| **Grant Permission** | `adb shell pm grant org.localdex android.permission.WRITE_SECURE_SETTINGS` |
| **Launch Server** | `adb shell CLASSPATH=/data/local/tmp/scrcpy-server.jar app_process / com.genymobile.scrcpy.Server 3.1 ... new_display=1920x1080/240` |
| **Force Freeform** | `adb shell wm set-display-windowing-mode -d <displayId> 5` |
| **PC DeX Mirroring** | `scrcpy --display-id=<displayId>` |
| **Enable Wireless ADB** | `adb shell settings put global adb_wifi_enabled 1` |

## 6. Known Platform Quirks

1. **Split-Screen Menu Option:** Selecting *Split-screen* from a window handle in One UI moves the app to the phone's primary display rather than inside DeX.
2. **DeX Decor vs. AOSP Freeform Decor:** Virtual displays use AOSP's drag-handle caption decor intentionally to avoid the One UI 8.5/9 SystemUI caption drag crash.
3. **Reboot Persistence:** `MainActivity.onResume()` checks `WRITE_SECURE_SETTINGS` and re-enables `adb_wifi_enabled = 1` automatically after reboots.
